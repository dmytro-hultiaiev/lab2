# НОРМИ КОДУВАННЯ КОМАНДИ ДЛЯ МОВИ JAVA

## 1. Правила іменування

1.1 Назви класів повинні використовувати стиль PascalCase.
Приклад: StudentManager, DroneController

1.2 Назви методів повинні використовувати стиль camelCase.
Приклад: calculateSpeed(), printReport()

1.3 Назви змінних повинні бути зрозумілими та використовувати camelCase.
Неправильно: x, a, bb
Правильно: currentSpeed, studentScore

1.4 Константи повинні записуватися великими літерами з підкресленням.
Приклад: MAX_SPEED, MIN_BATTERY_LEVEL

------------------------------------------------

## 2. Форматування коду

2.1 Відступ кожного вкладеного блоку – 4 пробіли.

2.2 Один оператор повинен розміщуватися на одному рядку.

2.3 Відкриваюча фігурна дужка ставиться в тому ж рядку.

2.4 Максимальна довжина рядка – 100 символів.

2.5 Логічні блоки коду повинні відокремлюватися порожнім рядком.

------------------------------------------------

## 3. Методи

3.1 Один метод повинен виконувати одну відповідальність.

3.2 Довжина методу не повинна перевищувати 30 рядків.

3.3 Назва методу повинна описувати його призначення.

3.4 Повторюваний код необхідно виносити в окремі методи.

------------------------------------------------

## 4. Класи

4.1 Клас повинен реалізовувати одну основну відповідальність.

4.2 Публічні поля класу заборонені.

4.3 Поля повинні бути private, доступ через методи.

------------------------------------------------

## 5. Умови та цикли

5.1 Не допускається надмірна вкладеність if.

5.2 При великій кількості варіантів слід використовувати switch.

5.3 Логічні вирази повинні бути зрозумілими.

------------------------------------------------

## 6. Константи та магічні числа

6.1 Числові значення необхідно замінювати іменованими константами.

Неправильно:
if(speed > 80)

Правильно:
if(speed > MAX_SPEED_LIMIT)

------------------------------------------------

## 7. Коментарі

7.1 Коментарі використовуються лише там, де код недостатньо зрозумілий.

7.2 Застарілі або непотрібні коментарі повинні видалятися.

------------------------------------------------

## 8. Обробка помилок

8.1 Порожні блоки catch заборонені.

8.2 Вхідні дані повинні перевірятися.

------------------------------------------------

## 9. Правила рефакторингу

9.1 Повторення коду → винесення в метод.

9.2 Довгий метод → розбиття на менші методи.

9.3 Великий клас → розподіл відповідальностей.

9.4 Невдалі назви → перейменування.

9.5 Мертвий код → видалення.
